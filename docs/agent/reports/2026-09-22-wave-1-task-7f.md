   riding on whatever a dependency-of-a-dependency happens to pull in. The

I checked before assuming the path:

- `cli/tests` does not exist.
- `cli/sushitrack_cli/services/tests.py` exists, but it is not a pytest test
  file — it is the `st test` command's own service module, wrapping CTest for
  this repository's C++ suites (`SUITE_LABELS = {"unit": ..., "integration":
  ..., "regression": ..., "functional": ...}`).
- A repo-wide search for `def test_` or `import pytest` outside
  `third_party/` and `build/` returned no matches anywhere in the tree.
- The only `tests/` directories in the repository (`./tests`,
  `third_party/TrackEval/tests`, `third_party/yolox/tests`) hold C++ sources
  and CMake files, not Python.

So there is no CLI test count to report for this repository — the suite
step 4 in the plan asks for produces 0 collected tests because there is
nothing to collect. I installed `pytest` into the throwaway venv to run the
check honestly rather than skip it; the "file or directory not found" result
above is pytest's real answer to `cli/tests`, not a fabricated substitute.
